# M3 Planning：证据优先编排实验

12 个真实样本全部成功提交并通过重启读回，但证据优先条件没有显示内容质量改善，不能依据 12/12 的生命周期结果启用优化。共 33 次计量请求、175,250 reported/charged tokens，未知 usage 为 0；未修改生产逻辑和默认模型。

实验使用国内 `api.minimax.cn`、现有累计资源账本，与多媒体及角色实验共享最多 4 个在途请求。三组独立合成来源各为两页可抽取 PDF：线性方程、抽球概率、Python 列表与字典。每组 baseline/证据优先各重复两次，共三个 family；重复不是独立来源。两臂统一 adaptive thinking、温度 0.1、输出 4096、每样本至多 8 次 wire。唯一编排差异是候选首个请求设置 `read_page_range_content` 的 function tool_choice。返回仍完整经过生产严格工具解析及 Planning admission/commit，没有替模型制造合法工具动作。

全部样本有真实 admitted Harness operation、`plan_generation` committed trace、有效物理页范围、原容器读回和新容器读回一致；读回没有新增 provider 调用。该证明不保证每个工具均成功，也不证明教材语义和教学效果。

逐条辅助复核发现以下可复现问题，详见 [机器可读审核](evidence/m3-planning-multimedia-2026-09-12/planning-audit.json)：

- `equations/evidence-first/0` 的六个工具全部因形状不符失败，但仍提交计划，将 a=0 写成“不构成方程”或“非方程”，没有准确保留比较 b 与 c 的教材处理。应先研究工具协议与失败后证据充分性，强制 tool_choice 本身不保证取证成功。
- 概率材料的 1/4 以“首抽红球且不放回”为条件。baseline/1 和 evidence-first/0 在最终教学表述中丢失这个条件；另外两个样本虽在局部写出红球或更新后的组成，单条任务仍有歧义。更严谨的下一轮需把条件保持作为冻结 rubric，并避免用户目标本身简写成“不放回不应为 2/5”造成引导混淆。无条件的第二次抽红边缘概率仍为 2/5。
- `python/baseline/0` 声称循环留到教材后续章节，来源没有后续章节；`python/evidence-first/1` 使用来源未给出的负索引和缺键报错。模型能写教学活动，但对“资料事实、可推导练习、扩展知识”的来源边界仍不稳定。

辅助复核由适配器作者进行，属于开发诊断，不能冒充独立留出认证。baseline 有 2/6 明确问题、1/6 局部歧义；候选为 3/6 与 2/6。样本很小，且工具形状错误集中在一个样本，不能声明显著差异。

当前 Planning 是一个模型驱动的有界工具循环，工具执行器、严格验证器和提交层由应用控制，并非多个独立推理 agent。真正的审阅角色可先在实验层只读输出“教材支持/条件丢失/超范围”结构化 finding，随后由独立修订 proposal 处理并重新验证，保留独立预算与失败分母；不应让 reviewer 自由重写已提交状态。本轮只测试证据优先，不把它称为多 agent 改善证据。
