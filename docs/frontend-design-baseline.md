# 前端设计基线

本文档是 `apps/web` 当前稳定界面的视觉与交互基线。新增页面或修复局部 UI 时，优先复用现有 class、CSS variable 和页面 block 模式；只有在组件确实需要独立行为时才增加新的局部规则。

## 设计方向

- 学习 UI 保持安静、清晰、内容优先；角色表现和 Debug Console 不与学习操作混用。
- 页面使用白色主背景、浅灰中性面板、teal 强调色。强调色用于主操作、当前状态、焦点和可确认的新增内容。
- 信息层级通过间距、边框、字重和背景明度表达，不用大面积渐变、厚重阴影或随意的彩色卡片。
- 详情、恢复、说明等次级信息默认折叠或弱化，不能抢占输入框和主操作的视觉焦点。

## 尺寸和间距

| 项目 | 基线 |
| --- | --- |
| 桌面侧导航 | 200px；移动端使用 48px 顶部导航 |
| 页面左右留白 | 桌面 28px；窄屏由布局规则压缩 |
| 常用间距 | 6 / 8 / 10 / 12 / 14 / 18 / 22px |
| 普通控件高度 | 44px，保证键盘与触控可用 |
| 小型图标按钮 | 36px 视觉尺寸；必要时由外层提供 44px 点击区域 |
| 复选框视觉尺寸 | 18px；点击区域至少 44px，不要把 checkbox 本体拉伸到 44px |
| 文本输入 | 最小高度 44px；多行输入通常 96px 起，可垂直调整 |
| 面板边框 | 1px `var(--border)`；仅在强调层级时使用 `var(--border-strong)` |
| 面板圆角 | 默认 0；已有明确卡片体系的组件可使用小圆角，但不要局部自创大圆角 |

## 颜色和文字

统一使用 `apps/web/app/globals.css` 的 token，不在组件内写新的十六进制颜色：

- 背景：`--bg`；普通面板：`--panel`；更强的面板层：`--panel-strong`
- 边框：`--border` / `--border-strong`
- 文字：`--ink`（主要）、`--ink-2`（次要）、`--muted`（说明）
- 主强调：`--accent`；悬停：`--accent-hover`；浅强调底：`--accent-soft`
- 语义反馈：`--positive`、`--negative`
- 正文使用 `--font-body`；代码、协议示例和技术标识使用 `--font-mono`

主按钮使用 teal 实底白字；次按钮使用白底、边框和深色文字；禁用状态统一降低不透明度并显示不可用光标。焦点状态必须保留可见 outline 或 accent 边框。

## 组件和图标

- 页面 block 使用已有稳定命名，例如 `Plan Workspace`、`Study Dialog`、`Study Console`、`Plan Revision Panel`。
- 详情块使用 `details/summary`，summary 至少 36px 高；重要页面折叠标题至少 52px 高，并使用统一的加号/减号指示器。
- 操作按钮应有明确的文字或 `aria-label`。图标只承担识别和节省空间的作用，不能替代关键操作文字。
- 当前导航、主操作、保存结果和错误提示使用现有 teal/semantic 体系；不要引入 emoji、随机 SVG 或与 `TopNav` 不一致的图标风格。
- 表格放在可横向滚动的 wrapper 中，表头、边框和长文本换行遵循现有中性表格样式。

## 响应式和可访问性

- 触控目标保持至少 44px；需要小视觉控件时，用外层扩大点击区域，而不是修改控件本体尺寸。
- 组件必须在 390px 宽度下不产生页面级横向滚动；长文本、代码和差异表允许在局部容器横向滚动。
- 表单控件保留可见 label 或可验证的 `aria-label`；异步状态使用 `role="status"`，错误使用 `role="alert"`。
- 颜色不能作为唯一状态提示；同时提供文字、边框、字重或图标变化。

## 修改检查清单

1. 是否复用了现有 token，而不是新增局部颜色、尺寸和圆角？
2. 主/次/危险操作是否符合按钮层级，次级说明是否被适当弱化？
3. 控件视觉尺寸和点击区域是否分别处理，尤其是 checkbox、icon button？
4. 390px 宽度、键盘焦点、屏幕阅读器名称和异步状态是否可用？
5. 是否需要补充页面 block 的 CSS class，而不是继续堆叠 inline style？
