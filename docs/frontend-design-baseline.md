# 前端设计基线

本文档定义 `apps/web` 的视觉与交互设计基线。新增页面或重构 UI 时优先复用既有样式类、CSS Token 与页面区块模式，只在组件确需独立行为时增加局部规则。

## 设计方向

- **安静、清晰、内容优先**：学习界面聚焦正文与操作，角色表现层与全局 Debug Overlay 不与学习流程混杂。
- **中性层次与单一强调色**：采用白色主背景、浅灰中性面板与 teal 强调色；强调色仅用于主操作、当前选中态、键盘焦点与待确认新增项。
- **克制的视觉表达**：通过留白、边框、字重与背景明度建立层级，避免大面积渐变、厚重阴影或随意彩色卡片。
- **次级信息退让**：恢复详情、系统说明与诊断摘要默认折叠或弱化，不抢占输入框与主操作按钮焦点。

## 尺寸与间距

| 项目 | 基线规范 |
| --- | --- |
| 桌面侧导航 / 移动顶导航 | 桌面 200px 侧栏；移动端 48px 顶栏 |
| 页面水平内边距 | 桌面 28px；窄屏随断点收紧 |
| 常用间距梯度 | `6 / 8 / 10 / 12 / 14 / 18 / 22px` |
| 常规控件高度 | `44px`（保障触控与键盘可用性） |
| 小型图标按钮 | `36px` 视觉尺寸；必要时由外层提供 `44px` 点击热区 |
| 复选框 | `18px` 视觉尺寸；点击热区至少 `44px`，不拉伸 checkbox 本体 |
| 文本输入框 | 单行最小高度 `44px`；多行通常 `96px` 起且可垂直缩放 |
| 面板边框与圆角 | `1px solid var(--border)`（强调层用 `var(--border-strong)`）；默认直角 `0`，已有卡片体系允许克制小圆角，不局部自创大圆角 |

## 颜色与字体 Token

统一使用 `apps/web/app/globals.css` 中定义的 CSS 变量及其 `@theme inline` 映射的 Tailwind CSS v4 语义类（如 `bg-bg`、`bg-panel`、`bg-panel-strong`、`border-border`、`text-ink`、`text-ink-2`、`text-muted`、`bg-accent`、`hover:bg-accent-hover`、`bg-accent-soft`、`text-positive`、`text-negative`、`font-sans`、`font-mono`），不在组件中硬编码十六进制颜色：

- **表面**：`--bg`（画布）、`--panel`（普通面板）、`--panel-strong`（强调面板）
- **边框**：`--border`、`--border-strong`
- **文字**：`--ink`（主要）、`--ink-2`（次要）、`--muted`（辅助说明）
- **强调**：`--accent`、`--accent-hover`、`--accent-soft`
- **语义**：`--positive`、`--negative`
- **字体**：正文使用 `--font-body`，代码、协议标识与技术参数使用 `--font-mono`

主按钮使用 teal 实底白字，次按钮使用白底深字加边框，禁用态统一降低不透明度并标示不可用光标；所有可交互元素必须保留可见焦点轮廓或强调边框。

## 组件与图标约定

- 页面区块严格沿用 [页面命名与术语](page-vocabulary.md) 中的标准命名。
- 折叠详情优先使用原生 `details/summary`：常规 `summary` 高度 ≥ `36px`，主区块折叠标题 ≥ `52px`，采用统一的加减指示器。
- 操作按钮须有明确文案或 `aria-label`；图标仅辅助识别，不替代关键文字。图标与 `TopNav` 保持同一套线性/Material 风格，不混入 emoji 或随意 SVG。
- 数据表格置于可横向滚动的容器中，遵守中性表头、边框与长文本换行规则。

## 响应式与可访问性

- 可点击目标至少 `44px`；小视觉控件通过外层扩展热区，不改变本体视觉比例。
- 在 `390px` 窄屏下不得出现页面级横向滚动；代码块、长文本与差异表仅在局部容器内横向滚动。
- 表单控件保留可见 `label` 或可验证的 `aria-label`；异步状态使用 `role="status"`，错误提示使用 `role="alert"`。
- 颜色不得作为唯一状态表达，须配合文案、字重、边框或图标变化。

## 修改检查清单

1. 是否全部复用既有 CSS Token，未在组件内硬编码新颜色、尺寸或圆角？
2. 主/次/危险操作层级是否清晰，次级说明是否适当弱化？
3. 视觉尺寸与触控热区是否分离处理（尤其是 checkbox 与图标按钮）？
4. 390px 窄屏、键盘焦点、无障碍标签与异步状态提示是否完整？
5. 样式是否优先使用 Tailwind CSS v4 语义工具类（并配合 `@layer components`），而不是继续堆叠 inline `style={{}}` 或 TS 样式对象？
