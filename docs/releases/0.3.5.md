# 0.3.5

本版本把真实数学书页实验中有效的 `Picture` / 独立 `Formula` 候选路径纳入 Study，并修复连续三个版本的 Desktop Release 发布门超时问题。完整实验方法、逐任务结果和保留证据见[M3 数学书页定位、Reflection 与 DocLayout-YOLO](../quality/m3-book-grounding-results-2026-09-12.md)。

## 已采用改动

- Study 新增纯读工具 `read_projected_pdf_layout_candidates`，通过默认关闭的外部 DocLayout-YOLO 子进程生成页级和单次递归候选。候选只接受 `Picture` 与独立 `Formula`，做 NMS 并限制为 32 项；正文、行内公式锚点与单字母继续由 OCR 路径处理。
- 模型可以选择离散候选，或在 `Picture` 母框内返回局部框；最终区域写入继续使用已有 `annotate_projected_pdf_region`。原页、候选页和母框 crop 联系表最多提供三张，仅作为 provider 图片证据，不进入公开 DTO 或 trace。
- worker、模型 revision、权重 SHA-256、标签和输出均受严格校验，异常时 fail closed。功能默认关闭，不把 Torch 或外部模型加入主安装依赖。
- Harness 更新到 `study-chat-toolset-v2`，登记 `study-visual-grounding-v1`；Python、TypeScript、Tool Manifest、workflow/stage registry 和 golden fixtures 保持一致。Study 工具由 31 个增至 32 个。
- Hatcher 证据已清理为 4 张实际测试页、对应目标标注和清单；数学书页定位证据只保留最新逐任务审核、两个 DocLayout-YOLO 结果 JSON 和最终可视化。

## 实测范围

8 个真实书页图形任务中，DocLayout-YOLO 页级 `Picture` containment 为 `8/8`，页级 tight candidate 为 `3/8`，单次递归为 `4/8`，一级与递归候选并集为 `5/8`。M3 接收母框与 crop 后返回母框内局部框，严格门通过 `6/8`；剩余两个失败样本分别为 Cartesian 小矩形和章节依赖图单节点。该结果来自开发集，不是 page-disjoint held-out 或独立专家认证。

坐标网格校准严格通过率仍为 `1/12 -> 1/12`，已归档为负面结果。多轮 Reflection 在原始 8 任务上由 `0/8` 提升到 R1 `2/8`、R2 `3/8`，R3 无新增并出现数值回退，因此没有采用无界反思循环。

## 许可与启用边界

仓库为 GPL-3.0；DocLayout-YOLO 代码为 AGPL-3.0，固定权重卡标 Apache-2.0。GPL-3.0 第 13 条允许与 AGPLv3 作品组合，但网络部署仍需履行组合中 AGPL 部分的附加源码提供义务。DocSynth300K 数据卡没有公开许可字段或许可正文，因此项目许可证不能代替训练数据授权证明。当前实现保持默认关闭的外部子进程边界，分发或托管启用前仍需完成依赖和数据许可复核。

## CI 与验证

`0.3.2`、`0.3.3` 和 `0.3.4` 的 Desktop Release 均在聚合的 `npm run check:release` 步骤运行到 GitHub Actions 360 分钟上限，无法从 job 状态区分卡点。按模块隔离后，第一次超时暴露在 `test_diagnostic_benchmark`，因此长期 SQLite reader/WAL 性能工作负载改由显式 `npm run bench:diagnostics` 执行，不再混入托管正确性门。随后 `test_diagnostic_desktop` 的线程栈确认真正的无限等待链：测试线程停在 `queue.join()`，diagnostic writer 则在 schema 初始化异常后无限重试，永远不对排队事件调用 `task_done()`。

GitHub hosted Python 所链接的 SQLite 不提供较新的 `unixepoch()` 函数，schema 初始化实际报错为 `OperationalError: no such function: unixepoch`。本版本将诊断事件、记录保留、writer coverage 和索引 SQL 全部改为兼容旧版 SQLite 的 `CAST(strftime('%s','now') AS INTEGER)`；writer 启动最多尝试五次，持续失败后关闭 admission、排空队列并释放等待者。模块 watchdog 仍为 180 秒，超时栈会写入独立文件并转成 Actions annotation，再终止或强杀子进程。

发布门同时拆成契约、Web 类型、Web reliability、Harness pilots、stage eval、plan revision eval、后端测试和 Web build 八个步骤；每步设置 5–25 分钟上限，job 总上限为 90 分钟，并新增 main 推送时运行的同构 Release Gate，在创建版本标签前完成 Ubuntu 验证。后端测试进一步按模块启动独立 Python 进程，每模块限制 180 秒；超时时先输出全部线程栈，再终止该模块并报告其名称，避免进程退出泄漏把整条发布流水线永久占住。

本地等价发布门已通过：868 项后端测试、共享契约、Web reliability、Harness pilots、十个 stage regressions 与 Next.js 生产构建均通过。提交 `107e3d0` 的远端 Release Gate `34704841204` 也已完整成功，用时 7 分 45 秒；它验证了 hosted SQLite、全部后端模块和 Web production build。`v0.3.5` Desktop Release 的最终状态以 GitHub Actions 为准。
