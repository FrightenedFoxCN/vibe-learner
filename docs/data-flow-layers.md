# 数据流分层与兜底责任

本规范确立一条核心原则：**缺失数据的默认值只在唯一归属层产生**。编写 `x or ""`、`payload.get("k", "")` 或 `?? ""` 前，先确认当前代码位于哪一层。

## 数据流分层

```text
① 外部输入（用户表单 / 上传附件 / 历史 JSON / 数据库旧行 / 模型输出）
   │  形状未知：缺键、null、类型错均可能出现
   ▼
② 归一化层（services/ai/app/core/coerce.py）
   │  将"无文本"统一收敛为明确的字符串或 None
   ▼
③ 域模型层（services/ai/app/models/*.py，Pydantic strict）
   │  受信任形状：必填字段缺失必须报错，不做二次兜底
   ▼
④ 持久化层（services/ai/app/persistence/*.py）
   │  数据库读写；历史缺列兼容集中于 _from_row 系列函数
   ▼
⑤ API DTO（services/ai/app/models/api.py 等）
   │  对外契约：显式声明字段可选性与默认值
   ▼
⑥ 前端 Decode（apps/web/lib/*-decode.ts）
   │  只校验线上形状（存在性、类型、枚举、范围），不发明语义默认值
   ▼
⑦ UI 组件（apps/web/components/*）
      仅允许纯展示兜底（空串占位、空列表折叠）
```

## 各层职责与禁令

| 层 | 允许 | 禁止 |
| --- | --- | --- |
| ② 归一化层 | 使用 `coerce.text_at` / `optional_text_at` 统一缺键、`null` 与类型异常 | 在此层裁决业务必填性 |
| ③ 域模型层 | Pydantic 严格校验与显式 `Field(default=...)` | 手工重复 `str(...)` 覆盖 Pydantic 校验 |
| ④ 持久化层 | 集中处理历史行缺列兼容读取 | 复制域模型层已有默认值 |
| ⑤ API DTO | 显式声明 `Optional` 或合法默认值 | 用 `""` 表达"字段不存在" |
| ⑥ 前端 Decode | 形状校验、跨字段一致性与版本检查 | 语义兜底（补空数组、空串或默认枚举） |
| ⑦ UI 组件 | 表单受控初始值、空值展示占位与空区块隐藏 | 将展示兜底值回写为业务提交载荷 |

## 后端归一化函数边界

位于 `services/ai/app/core/coerce.py`：

| 函数 | 语义 | 适用场景 |
| --- | --- | --- |
| `text_or_empty(value)` | 将假值（`None`、`""`、`0`、`False`、`[]`）归一为 `""`，其余转为 `str` | 仅用于纯文本字段的空值归一化 |
| `text_at(mapping, key)` | `text_or_empty` 的映射取键版 | 从外部 JSON、旧行或模型输出读取纯文本字段 |
| `optional_text(value)` | 保留 `None`，非空值转为 `str` | "缺失"与"空字符串"具有不同语义，或需保留 `"0"` 时 |
| `optional_text_at(mapping, key)` | `optional_text` 的映射取键版 | 同上 |

当字段值可能为数字 `0` 或布尔值且不能丢失语义时，必须使用 `optional_text` / `optional_text_at` 并显式处理缺失分支。

## 前端空值合并边界

前端中的 `?? ""` / `|| ""` 按归属层区分处理：

- **允许**：UI 组件与 Hook 中的表单输入受控默认值、展示文本占位；请求构造层（`lib/api/`）中明确的线上可选字段表示；本地编辑器草稿归一化。
- **禁止**：在 `lib/*-decode.ts` 中用默认值掩盖后端缺失字段或错误类型。解码器中的比较断言须确保缺失字段依然触发带路径的失败错误。

## 修改检查清单

涉及字段读取或序列化改动时，逐项确认：

1. 该字段缺失时业务上是否允许继续？允许则在归一化层给默认值；不允许则在域模型层声明为必填。
2. 对应默认值是否已在 `coerce` 或 Pydantic 模型中定义？避免跨层重复兜底。
3. 前端 decode 是否做了语义填补？若是，移除填补并保持 fail-closed；若是 UI 展示兜底，确保不污染提交载荷。
