# 数据流分层与兜底责任

这份文档固定一条规则：**缺失数据的默认值只在唯一的归属层产生**。任何时候想写
`x or ""`、`payload.get("k", "")`、`?? ""`，先确认自己在哪一层。

## 五层

```
外部输入（用户表单 / 附件 / 旧 JSON / SQLite 行 / 模型输出）
   │  ① 形状未知：缺键、null、类型错 都可能出现
   ▼
归一化层  app/core/coerce.py
   │  ② 把"没有文本"变成一个明确的字符串或 None
   ▼
域模型层  app/models/*.py（pydantic，strict）
   │  ③ trusted shape：必填字段缺失必须抛错，不再兜底
   ▼
持久化层  app/persistence/*.py
   │  ④ 读写数据库；旧行兼容在这里统一处理
   ▼
API DTO  app/models/api.py
   │  ⑤ 对外契约：字段可选性显式声明
   ▼
前端 decode  apps/web/lib/*-decode.ts
   │  ⑥ 只校验形状，不发明语义默认值
   ▼
UI 组件
      ⑦ 纯展示兜底允许保留
```

## 每层的责任与禁止事项

| 层 | 允许 | 禁止 |
|---|---|---|
| ① 外部输入 | — | — |
| ② 归一化 | `coerce.text_at` / `optional_text_at` 把缺键、null、类型错统一 | 在这里判断业务必填性 |
| ③ 域模型 | pydantic 校验 + 显式 `Field(default=...)` | 手工 `str(...)` 再做一遍 pydantic 的工作 |
| ④ 持久化 | 旧行缺列的兼容读取（集中在一个 `_from_row` 系列） | 把模型层的默认值再复制一遍 |
| ⑤ API DTO | 显式声明 `Optional` / 默认值 | 用 `""` 表达"没有这个字段" |
| ⑥ 前端 decode | 形状校验（字段存在、类型、长度） | 语义兜底（空数组、空串、默认枚举） |
| ⑦ UI | 展示兜底（空串渲染成占位、空列表隐藏区块） | 把兜底结果回写给状态或提交 |

## 两个帮助函数的语义边界

`app/core/coerce.py`：

| 函数 | 语义 | 何时用 |
|---|---|---|
| `text_or_empty(value)` | 严格等价于历史写法 `value or ""` 再 `str()`：**假值（`0`、`False`、`[]`）也变 `""`** | 只用于"没有文本"的归一化，且替换的是既有 idiom |
| `text_at(mapping, key)` | 上者的字段版 | 外部 JSON、旧行、模型输出读字段 |
| `optional_text(value)` | 保留 `None`，其余转字符串 | "缺失"与"空串"语义不同时 |
| `optional_text_at(mapping, key)` | 上者的字段版 | 同上 |

**注意**：`text_or_empty` 有意保留历史的假值行为，它是「行为等价」的收敛步骤，不是最终语义。
需要 `0` 保持为 `"0"` 的调用点应改用 `optional_text_at` 并显式决定默认值。

## 修改检查清单

改到数据读取时：

1. 这个字段缺失时，业务上还能继续吗？能 → 归一化层给默认；不能 → 域模型层设为必填。
2. 这个默认值是不是已经有别人定义过？先搜 `coerce.` 和对应 pydantic 模型。
3. 前端是否又兜了一遍？如果是 decode 里的，删掉；如果是 UI 渲染的，保留并注明。
